# 0.2 scope and progress

Branch: `feat/dayframe-mvp-2`. Approved scope: local storage, compatible backups, Fedora/macOS delivery, documentation/download portal, and early Apple feasibility evidence. Accounts, services, sync, E2E encryption, phone UI, TODOs, and widgets belong to later work.

## Implemented in the first chunk

- SQLite version 1 → 2 migration in one transaction, preserving the original `planner` table as `planner_v1_backup`.
- Entity records, stable IDs/order, local revisions and content-free deletion markers; atomic saves/restores and future-schema rejection.
- Existing planner/backup JSON format and calendar time rules retained.
- Storage regression tests and a native migration test using a shared, isolated v1 fixture.
- Damaged legacy data leaves the database unchanged and displays an error in the app; persistence remains blocked until the data is repaired.
- Host-specific desktop build scripts and macOS DMG configuration.
- A macOS native CI job; no release or service deployment is triggered.
- Concise README, installation/contributor guides, accepted milestone roadmap, and ready-to-copy GitHub templates.

### PR #2 follow-up

At commit `8f9edbb`, [PR #2's checks](https://github.com/joeydano/dayframe/pull/2/checks) passed for the frontend (including browser tests), Linux native build/tests, and macOS native build/tests. Mac source startup was subsequently confirmed as recorded below; full feature, iPhone, and installer checks remain pending.

The first Mac source-build attempt stopped in Vite before the native app started: the log showed unsupported Node.js 22.1.0 and a missing Rolldown Apple Silicon binding. The lockfile already includes that binding. Setup follow-up adds `.nvmrc` for Node 24, npm engine enforcement, explicit optional dependencies in CI/install instructions, and Mac troubleshooting that preserves the lockfile. This does not change the application or its dependencies.

The next Mac log confirmed the Rolldown binding was installed, then failed in Cargo while resolving `js-sys` features. The owner reported Rust/Cargo **1.60.0**, selected through rustup's `stable-aarch64-apple-darwin` toolchain. Published metadata also shows that the repo's old Rust 1.77.2 declaration was below the locked Tauri requirement (1.90). The follow-up selects the locally tested Rust/Cargo 1.98.1 in `rust-toolchain.toml`, the package requirement, and CI; it adds explicit-toolchain troubleshooting without changing dependency versions. All 16 Rust tests passed locally with the unchanged lockfile on Rust/Cargo 1.98.1.
